# 全流程优化策略

## 一、幻觉抑制方案

### 1.1 Prompt 层面优化

**核心策略：严格约束 + 引用标注 + 诚实告知**

```
核心原则：
1. 严格基于文档：所有回答必须完全基于提供的参考文档内容
2. 诚实告知：如果文档中没有答案，明确说不知道
3. 引用标注：每个关键信息都必须标注来源
4. 准确优先：宁可简短准确，也不要为了全面而牺牲准确
```

**实现方式：**
- 系统 Prompt 中明确角色设定和行为约束
- 要求模型在回答中标注 [来源N] 引用标记
- 明确禁止编造、推测、引入外部知识
- 设计回答结构：直接回答 → 详细说明 → 引用来源

### 1.2 检索层面优化

**核心策略：提升召回率和准确率，确保相关文档被检索到**

| 优化手段 | 说明 | 效果提升 |
|---------|------|---------|
| 混合检索 | 向量检索 + BM25 关键词检索双通道 | 召回率 +20% |
| Rerank 精排 | 从 top_k 中精选 top_n | 准确率 +15% |
| 问题改写 | 结合历史上下文优化问题 | 多轮场景 +10% |
| 智能分块 | 语义边界分块 + 重叠 | 上下文完整性 +25% |

### 1.3 答案验证机制

**核心策略：回答生成后进行幻觉检测**

- 引用一致性检查：验证回答中的事实是否都能在引用文档中找到
- 关键信息比对：数字、日期、名称等精确信息与原文比对
- 置信度评估：对回答的可靠性进行评分

## 二、检索准确率优化

### 2.1 混合检索架构

```
用户问题
    │
    ├─→ 向量检索（语义匹配）
    │   └─ 嵌入模型 → 向量数据库 → 相似度计算
    │
    ├─→ BM25 检索（关键词匹配）
    │   └─ 倒排索引 → 词频统计 → BM25 评分
    │
    └─→ 结果融合
        ├─ 去重合并
        ├─ 加权融合（向量权重 0.6 + BM25 权重 0.4）
        └─ 分数归一化
            │
            ↓
        Rerank 精排
            │
            ↓
        最终结果
```

### 2.2 向量检索优化

**嵌入模型选择：**
- OpenAI text-embedding-3-small：平衡效果和成本
- BGE 中文系列：中文场景优化，本地部署
- 多语言模型：支持中英文混合场景

**检索参数调优：**
- Top K：10-20（平衡召回率和噪声）
- 相似度阈值：0.5-0.7（过滤低质量结果）
- 元数据过滤：按文件、类型等条件过滤

### 2.3 BM25 检索优化

**中文分词：**
- jieba 分词：准确的中文分词
- 停用词过滤：去除无意义的停用词
- 同义词扩展：提升召回率

**参数调优：**
- k1 = 1.5：词频饱和度参数
- b = 0.75：文档长度归一化参数

### 2.4 Rerank 重排优化

**重排模型选择：**
- BAAI/bge-reranker-large：中文效果优秀，开源可本地部署
- Cohere Rerank：商业 API，效果极佳

**重排策略：**
- 初始检索 top_k = 20
- 重排后返回 top_n = 5
- 交叉编码器计算精确相关性

## 三、文档处理优化

### 3.1 智能分块策略

| 文档类型 | 分块策略 | 块大小 | 重叠 |
|---------|---------|--------|------|
| PDF | 递归字符分块 | 512 字符 | 64 字符 |
| Word | 递归字符分块 | 512 字符 | 64 字符 |
| PPT | 按页分块 | 512 字符 | 32 字符 |
| Markdown | 标题分块 | 自适应 | 自适应 |
| Excel/CSV | 按行分块 | 1024 字符 | 0 |
| 纯文本 | 递归字符分块 | 512 字符 | 64 字符 |

**分块原则：**
1. 优先在语义边界分割（段落、句子）
2. 相邻块保留重叠，避免上下文断裂
3. 保留完整元数据，便于溯源
4. 按文档类型调整分块参数

### 3.2 增量更新机制

**基于文件哈希的增量检测：**
```
文件扫描 → 计算 MD5 哈希 → 与元数据比对
    ├─ 新增文件 → 解析 → 分块 → 入库
    ├─ 修改文件 → 删除旧版本 → 重新解析入库
    ├─ 未变文件 → 跳过
    └─ 删除文件 → 从知识库中删除
```

**优势：**
- 大幅提升更新效率（只处理变化的文件）
- 节省计算资源
- 支持批量增量更新

## 四、多轮对话优化

### 4.1 问题改写

**核心思路：** 结合对话历史，将用户当前问题改写为独立完整的问题

**示例：**
```
用户1：什么是 RAG？
助手1：RAG 是检索增强生成...

用户2：它有什么优势？
        ↓ 改写
用户2'：检索增强生成（RAG）有什么优势？
```

**效果：**
- 提升多轮对话的检索准确率
- 解决指代消解问题
- 保持对话连贯性

### 4.2 对话历史管理

**滑动窗口机制：**
- 保留最近 N 轮对话（默认 10 轮）
- 超出窗口的对话被截断
- 控制 token 消耗

**Token 控制：**
- 实时计算历史 token 数
- 超过阈值时从前往后删除
- 保证上下文在模型限制内

## 五、性能优化

### 5.1 批量处理

- 文档批量解析和分块
- 批量向量化（减少 API 调用次数）
- 批量检索和重排

### 5.2 缓存机制

- 嵌入结果缓存：相同文本直接返回缓存
- 检索结果缓存：相同查询直接返回缓存
- LLM 响应缓存：完全相同的问题直接返回

### 5.3 异步处理

- 文档上传异步处理
- 流式输出提升体验
- 非阻塞 UI 交互

## 六、准确率评估指标

| 指标 | 说明 | 目标值 |
|------|------|--------|
| 召回率 (Recall) | 相关文档被检索到的比例 | ≥ 90% |
| 精确率 (Precision) | 检索结果中相关的比例 | ≥ 80% |
| Top-5 准确率 | 前 5 个结果包含正确答案的比例 | ≥ 95% |
| 回答准确率 | 回答正确的比例 | ≥ 90% |
| 幻觉率 | 回答中包含编造内容的比例 | ≤ 5% |
| 引用准确率 | 引用来源正确的比例 | ≥ 95% |

## 七、常见问题与解决方案

### 7.1 检索不准

**问题表现：** 检索到的文档与问题不相关

**解决方案：**
1. 调整分块大小（尝试 256/512/1024）
2. 增加 top_k 值
3. 启用 Rerank 重排
4. 优化问题改写
5. 检查文档质量

### 7.2 回答幻觉

**问题表现：** 回答中包含文档中没有的内容

**解决方案：**
1. 加强 Prompt 约束
2. 增加引用标注要求
3. 降低 temperature（0.1-0.3）
4. 增加检索结果数量
5. 启用答案验证

### 7.3 上下文丢失

**问题表现：** 分块导致上下文不完整

**解决方案：**
1. 增加分块重叠比例
2. 增大分块大小
3. 使用父子分块策略
4. 增加上下文窗口

### 7.4 多轮对话理解差

**问题表现：** 无法理解上下文指代

**解决方案：**
1. 启用问题改写
2. 增加历史轮数
3. 优化对话 Prompt
4. 使用更强大的模型
